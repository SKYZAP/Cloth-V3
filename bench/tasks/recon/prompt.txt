In this empty folder, build a small Node.js command-line tool. Use Node 22 and only Node's standard library: no npm dependencies.

Command: node reconcile.mjs <orders.csv> <stock.json>

orders.csv
- First line is exactly the header: order_id,sku,qty,unit_price,status
- RFC 4180 CSV: fields may be wrapped in double quotes, quoted fields may contain commas, and "" inside a quoted field means one quote character. Fields never contain line breaks.
- Accept LF or CRLF line endings, an optional UTF-8 BOM, and ignore empty lines.
- qty must be a positive integer. unit_price must be a non-negative number with at most 2 decimal places (e.g. 5, 0.5, 19.99). status is one of paid, refunded, cancelled.

stock.json
- An object keyed by SKU: { "A1": { "on_hand": 10, "name": "Mug" }, ... }

Rules
- Every data row is validated, whatever its status and even if it is a duplicate.
- If an order_id appears more than once, only its first row counts; later rows with that id are ignored and the id is reported as a duplicate.
- cancelled rows are ignored.
- paid: subtract qty from the SKU's stock and add qty × unit_price to revenue.
- refunded: add qty back to the SKU's stock and subtract qty × unit_price from revenue.
- A SKU that isn't in stock.json is reported as unknown and changes neither stock nor revenue.
- Money must be exact (no floating-point drift).

Output: print JSON to stdout and exit 0:
{
  "revenue": number,              // e.g. 84.98
  "stock": { "<sku>": number },   // on_hand after applying the orders, for every SKU in stock.json
  "oversold": ["<sku>"],          // SKUs whose stock ended below 0, sorted
  "duplicates": ["<order_id>"],   // each duplicated id once, sorted
  "unknown_skus": ["<sku>"]       // sorted, each once
}

Errors: if a file can't be read, stock.json isn't valid JSON, the header is wrong, or any row is invalid (bad qty, bad unit_price, unknown status, wrong number of columns), print nothing to stdout, print one message to stderr starting with "line N: " (N = the 1-based line number in the file; the header is line 1) followed by the reason (mention qty, price, status or columns as appropriate), and exit 1. Problems not tied to a line just need a clear message and exit 1.
